# DSA Solving Guide

Use this method for every coding interview problem.

## Problem Template

```text
Problem:
Input:
Output:
Constraints:
Brute force:
Optimized approach:
Data structure:
Time complexity:
Space complexity:
Edge cases:
Final code:
Dry run:
```

## Interview Approach

1. Restate the problem in your own words.
2. Ask about constraints and edge cases.
3. Start with brute force.
4. Optimize using the right data structure or algorithm.
5. Explain time and space complexity.
6. Write clean code.
7. Dry run with at least one example.
8. Test edge cases.

## Common Patterns

| Pattern | Usually used for |
| --- | --- |
| Hash map | Frequency, lookup, duplicates, complements |
| Two pointers | Sorted arrays, pairs, palindrome, partitioning |
| Sliding window | Subarrays/substrings with constraints |
| Stack | Next greater element, valid parentheses, monotonic problems |
| Binary search | Sorted data, answer search, lower/upper bound |
| Heap | Top K, streaming median, scheduling |
| BFS | Shortest path in unweighted graph, levels |
| DFS | Traversal, connected components, recursion |
| Topological sort | Dependencies, course schedule |
| Union find | Components, connectivity, cycle detection |
| Backtracking | Combinations, permutations, search space |
| Dynamic programming | Overlapping subproblems, optimal choices |

## Edge Case Checklist

- Empty input
- Single element
- Duplicate values
- Negative numbers
- Already sorted input
- Reverse sorted input
- Very large input
- No valid answer
- Multiple valid answers
- Ties
